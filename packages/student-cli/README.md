# Student CLI

This package is the local, tool-neutral student interface for a Volta simulation. It records only official simulation actions and the reasoning the student deliberately supplies. It does not inspect the student's editor, agent, shell history, environment, processes, credentials, or unselected files.

The production command derives the assignment root from the current Git checkout, uses fixed gitignored `.volta-sim` session and pending-submission records, and connects only to the service origin embedded in the release. A caller cannot replace any of those destinations with command-line flags. The service pins the assignment's committed `.gitignore` blob; the CLI compares its working bytes and asks Git to confirm both records are ignored before using them. This local increment deliberately embeds a non-routable `.invalid` origin; an approved hosted release must replace it during trusted packaging. Operation IDs are limited to 160 safe characters, repeated inputs are bounded, service responses are cancelled before parsing if they exceed 1 MB, and one hard deadline covers both response headers and body.

The guided journey includes `login`, `resume`, `status`, `talk`, `evidence` (also available as `request`), `collect`, `advance`, `ledger`, `decision`, `estimate`, `requirement`, `claim`, `criterion`, `criterion-remove`, `calculation`, `calculation-remove`, `draft`, `checkpoint`, `review-request`, `submit`, and `logout`. Run `volta-sim --help` to discover the journey or `volta-sim help <command>` for every allowed value, tuple format, and a complete example. Prompts ask the student for their own evidence, expected evidence, estimates, rationale, pivot/stop conditions, target, failure threshold, and buy/build/no-build choice. They do not provide a score or expected answer. Declining suggested review creates no request; an accepted request is non-blocking and a later response is shown through a bounded projection.

`status` is the working-draft readback. It shows the authored constraints, unacceptable outcomes, response families, difficulty, persona and evidence briefs, available collection IDs, released official facts, the student's captured ledger, exact captured-evidence IDs, editable success-criterion IDs, and the same readiness report used by `submit`. A fact ledger action also prints the new evidence IDs immediately. Decision, requirement, and competency references use those evidence IDs, not the released fact ID. The client turns allowlisted service error codes into fixed correction instructions and never prints arbitrary server error text.

Success-criterion target dates may use the student-friendly `YYYY-MM-DD` form, which the CLI stores as midnight UTC, or a full ISO 8601 datetime with an explicit offset. Invalid calendar dates fail before a service action is sent. Recording a criterion returns its stable working-draft ID. `criterion-remove --id <criterion-id>` removes an erroneous entry from the working draft while preserving the full original criterion and removal in immutable, attempt-scoped reasoning history; the student can then add the corrected criterion.

Calculations are recomputed before they are recorded. Wrong arithmetic and unsupported arithmetic or unit combinations are rejected without saving a calculation or successful receipt. `status` and the recording response show calculation IDs. Use `calculation-remove --operation-id <new-id> --id <calculation-id>` to remove a mistaken draft calculation, including an older invalid entry, then record the correction. The original calculation and removal remain in attempt history. These checks do not judge whether the student's assumptions or estimate are sensible; staff does that.

Private `.volta-sim` files must never be committed, even with `git add --force`. Verification rejects them in both the current commit and its permitted history. If that happens, stop sharing that history and ask Volta staff for recovery help; deleting the current copy is not sufficient.

Build and pilot submissions capture only `.txt`, `.md`, `.csv`, and `.json` paths explicitly supplied with `--artifact`. Their status separates a complete reasoning base from the still-required artifact and does not claim the submission is ready until a tracked artifact is selected. Students can commit their own progress and new files normally. The checkout must retain the assigned GitHub origin, descend from its starting commit, and preserve its protected `.gitignore`. Every selected file must be a regular, bounded, tracked file whose working bytes match the current committed version. Verification does not invoke diff drivers, text conversion, clean/smudge filters, or a repository-configured filesystem monitor. The connected local pilot independently reads the assigned checkout again before accepting the selected commit, files, and bytes; it never accepts client claims alone. A service without that independent readback still accepts only its pre-verified commit and blobs. Hosted support for student progress requires equivalent trusted repository readback. No-build submissions select no artifact, and that rule is enforced before capture and again by the shared packet contract.

Before transmission, a submission is saved to the ignored user-only pending record. If the service commits it but its response is lost, rerunning `submit` with the same operation ID sends that exact packet and reconciles the stored result. Mutation receipts are scoped to one attempt: reopening archives the old receipts with that attempt and permits the same ID to describe new work in the new attempt. Login replay returns a token only while that exact token remains active. The record is removed only after a usable submission response; a rejected submission returns a nonzero exit code.

The repository-level `npm run pilot:local` command also starts this mock service as an explicitly local, public, non-assessed pilot. Its service-owned state remains outside the generated assignment checkout and reaches the student only through the same allowlisted HTTP projection used by the hosted client. The separate `volta-sim-local` command accepts only the pilot-generated manifest in that checkout; it cannot replace the production command's fixed origin. This is not a substitute for hosted GitHub pairing, service authorization, or production repository readback.

The local pilot resolves the actual question against the frozen authored routes. Unavailable or prerequisite-blocked questions release no facts. Authored time consequences are preserved, and public collection opportunities remain discoverable. Scripted responses remain available only for older explicitly scripted test fixtures.

Local student and staff actions share an assignment lock, so simultaneous requests and exact retries preserve acknowledged work. A killed owner's lock can be recovered without taking ownership from a live process. A busy timeout tells the caller to retry the same operation ID. This is a same-machine pilot mechanism, not a distributed transaction: a crash between the separate student and staff file writes can still require reconciliation. Unknown owners and reused live process IDs remain conservatively busy; staff should investigate with the local services stopped. A process killed before acquiring its lock may leave an unused private claim directory, which does not block the assignment.

Node can prevent following the selected final symlink and this package rechecks every selected ancestor after reading. A filesystem administrator could still swap an ancestor between individual operating-system checks. Hosted acceptance must therefore fetch the selected blobs from the pinned GitHub commit and treat that readback as authoritative.
